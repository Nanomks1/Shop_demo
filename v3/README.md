# محل عزيز — إدارة المخزون والصيانة (v3)

تطبيق ويب تقدّمي (PWA) بالعربية واتجاه RTL، مصمَّم للهاتف أولاً، يدير محل هواتف: المخزون (هواتف، أنتي كاس، بوشيط، إكسسوارات)، التعبئة، الصيانة، المستعمل، الديون، التقرير اليومي، مع مزامنة اختيارية بين الأجهزة ونسخ احتياطي.

- **لا خادم خاص ولا عملية بناء:** ملفات ثابتة (HTML/CSS/JS عادي بلا أي إطار عمل) تعمل مباشرة من مجلد `v3`.
- **يعمل بلا إنترنت:** كل البيانات محفوظة في الهاتف أولاً، والمزامنة تضيف نسخة مشتركة بين الأجهزة.
- **يُثبَّت كتطبيق:** عبر `manifest.json` (وضع standalone، اتجاه عمودي، أيقونتان 192 و512).
- **مفتاح التخزين `shop3`** هو نفسه المستعمل في v2، فبيانات v2 تعمل في v3.

## 2. الأقسام والميزات

### الشاشة الرئيسية
- شبكة من **6 أقسام**: الهواتف، الأنتي كاس، البوشيط، الإكسسوارات، التعبئة، طلبات الزبائن. تحت كل قسم سطر ملخّص (عدد القطع، نافد/قارب على النفاد، عدد الطلبات…).
- شريط «نظرة سريعة» وبطاقات تنبيه (مثل «لم يُرسل تقرير اليوم بعد»). يمكن إخفاء التنبيهات اليومية عن موظف معيّن.
- أيقونة عائمة ذكية (FAB) في الرئيسية فقط، قابلة للتعطيل.
- شريط تنقل سفلي: الرئيسية · الصيانة · التقرير · المزيد.

### البحث الموحّد
- بحث واحد يغطي المخزون والصيانة وطلبات الزبائن ودليل أسعار الإصلاح، مع بطاقة **كاشف الأثمنة** الفورية.
- توحيد الكتابة: يتجاهل التشكيل، يوحّد `أ إ آ` و`ى ي`، يحوّل الأرقام العربية إلى لاتينية، ويفهم أسماء الماركات بالعربية (مثل «ايفون» = iPhone، «سامسونج» = Samsung).

### المخزون
- **الهواتف:** بطاقة لكل هاتف، إضافة مع اقتراح الملحقات، حجز لزبون، سجل حركات، IMEI، عرض مضغوط.
- **الأنتي كاس:** مجموعات حسب الموديلات، ومستويات/أنواع الزجاج (عادي، Super Full Glue، Privacy…).
- **البوشيط:** سطر واحد لكل موديل، دائرة لكل لون بعدده وحدّها بلون الحالة؛ نافذة − / + لكل لون.
- **الإكسسوارات:** حسب النوع (كابل، شاحن، رأس شاحن، USB، كارت ميموري، سماعة، باور بانك)، الموصل (micro, type-c, lightning)، القدرة بالواط، ومجموعات الكابلات والشواحن.
- **حالة المخزون بالألوان:** متوفر (أخضر) · قارب على النفاد (برتقالي) · نفد (أحمر)، والحدود قابلة للتعديل (القسم 5).
- **الجولة اليومية (الجرد):** تأكيد الأصناف تباعاً؛ الصنف غير المؤكَّد لعدد أيام معيّن يُعتبر قديماً.
- **الباركود وIMEI:** مسح بالكاميرا أو إدخال، والبيع السريع المتتالي.
- **الوسوم:** كل القوائم (ماركات، ألوان، سعات، RAM، نوع الإكسسوار، موصل، فئات سعرية، أنواع الزجاج، القدرة، أعطال الصيانة) تُدار من شاشة واحدة، ويُدمج الجديد منها عند المزامنة بين هاتفين.
- **الحقول:** يمكن إظهار/إخفاء حقول كل قسم وإضافة خانات مخصصة.

### التعبئة
- رصيد هاتف واحد لكل مشغّل (IAM وORANGE وINWI) وبطاقات الشحن بفئات 5/10/20/50.
- حالة كل بطاقة بضغطة: متوفر / قارب / نفد، وزر «تم» في التقرير يسجّل الرصيد الجديد أو الكمية الواصلة مع حفظ فوري وتراجع.
- التحديث يتم في مكانه بلا إعادة رسم كي لا تُغلق لوحة المفاتيح.

### الصيانة
- **التبويبات:** في المحل · جاهز · لم تُصلَّح · الأرشيف. «لم تُصلَّح» = تعذّر الإصلاح أو رفضه (الحالة تبقى «جاهز»).
- **رقم التذكرة القصير:** `#A101` … `#Z999`، مع ضمان فرادته حتى عند العمل بلا إنترنت (يُصحَّح بعد المزامنة).
- **الاستلام:** اسم الزبون ورقمه والجهاز والعطل (وسوم أعطال ملوّنة)، السعر المتفق، العربون، مكان الهاتف (عند المعلم / الرف)، رمز القفل أو نمطه، IMEI، حالة الجهاز (شاشة مكسورة، بدون SIM، مطفأ، البصمة لا تعمل، بدون غطاء)، ملاحظة، وصورة بالكاميرا. إكمال تلقائي للزبائن والأجهزة.
- **التسليم:** نتيجة الإصلاح (تم / تعذّر / رفض)، **تجربة الجهاز مع الزبون إجبارية عند الإصلاح**، المتبقي بعد العربون، مدة الضمان (بلا، 3، 7، 15، 30 يوماً)، إرفاق سلعة من المخزون، وتنبيه إن كان على الزبون دين مفتوح.
- **واتساب:** رسالة جاهزية الهاتف فقط (برقم التذكرة وIMEI والضمان).
- **الضمان والتنظيف:** بعد مرور مدة (افتراضياً 30 يوماً) على التسليم تُمسح الصورة ورمز القفل. أرشفة (حذف الصيانات المسلّمة منذ أكثر من سنة وانتهى ضمانها) يدوياً وللمدير فقط.
- **دليل أسعار الإصلاح:** مع فلاتر سريعة ودعم سعرين (فئتين).
- **طلبات الزبائن:** «زبون سأل ولم نجد» مع الاتصال والواتساب والتعديل.

### المستعمل والديون والإحصائيات (`extra.js`)
- **شراء المستعمل:** سجلات شراء بصور تُحفظ في IndexedDB (مشتركة مع صور الصيانة)، وإكمال اسم الزبون من رقمه.
- **الديون:** تجميع حسب الزبون، تذكير واتساب، وربط حي مع الصيانة.
- **الإحصائيات:** الأعطال (مع تقسيم الأعطال المركّبة بالفاصلة) وطلبات الزبائن.

### التقرير اليومي
- شاشة تقرير تجمع أسطر المخزون والتعبئة (نافد / قارب) ويُنسخ كنص واتساب.
- إعدادات تنطبق على كل الأجهزة: العنوان، التذييل، ما يظهر، ساعة بدء التذكير (افتراضياً 16)، و**الشراء السريع** بضغطة واحدة من التقرير.
- إدخال كمية مخصصة يدوياً (`#`) للأنتي كاس ومجموعات الإكسسوارات من التقرير.

### المزيد (الإعدادات)
ثلاث مجموعات:
1. **المحل:** صفحة لكل قسم تجمع وسومه وحدوده (+ إعدادات الصيانة والتعبئة والتقرير والإحصائيات).
2. **المظهر والقفل:** الثيم وحجم الخط والزر العائم، رمز القفل السريع والقفل التلقائي.
3. **الإدارة والبيانات:** المستخدمون والصلاحيات، المزامنة، النسخ الاحتياطي، سلة المحذوفات.

### المظهر
- وضع (تلقائي / نهاري / ليلي) × لون (أزرق / أخضر / بنفسجي / برتقالي)، وحجم خط (الافتراضي 18).

## 3. نموذج البيانات

كل الحالة كائن واحد `S` يُحفظ كـ JSON تحت المفتاح `shop3`. الدالة `load()` تدمج المحفوظ مع القيم الافتراضية `DEF`، فإضافة حقل جديد إلى `DEF` آمنة مع البيانات القديمة.

| الحقل | المعنى |
|---|---|
| `items` | الهواتف |
| `gg` | مجموعات الأنتي كاس |
| `guide` | دليل أسعار الإصلاح |
| `ag` | مجموعات الإكسسوارات (كابلات، شواحن) |
| `rp` | الصيانة |
| `req` | طلبات الزبائن |
| `used` | المستعمل |
| `debt` | الديون |
| `tp` | التعبئة |
| `fields` | الخانات المخصصة |
| `trash` | سلة المحذوفات (للاسترجاع) |
| `tags` | القوائم (الماركات، الألوان…) |
| `users` / `me` / `pin` | المستخدمون، المستخدم الحالي، رمز المدير |
| `perm` | الصلاحيات |
| `cfg` | إعدادات (الخط `fs`، الثيم `th`، الحدود، إعدادات التقرير `rc`…) |

### أماكن التخزين

| المكان | المفتاح | المحتوى |
|---|---|---|
| localStorage | `shop3` | كل الحالة `S` (بلا صور) |
| localStorage | `shopErr` | سجل الأخطاء المحلي |
| localStorage | `shopSyncCfg` · `shopSyncSt` · `shopSyncTok` | إعداد المزامنة وحالتها وجلستها |

| sessionStorage | `admOk` | أن المدير أدخل رمزه في هذه الجلسة |

> الصور تُحفظ خارج `shop3` (في IndexedDB) حتى لا تمتلئ مساحة localStorage.

## 4. المستخدمون والأمان

- **الأدوار:** مدير وموظف. رمز الموظف إجباري (4 أرقام على الأقل). رمز المدير يُغيَّر من شاشة المستخدمين.
- **تخزين الرموز:** SHA-256 مع ملح، والرموز القديمة تُقبل ثم تُحدَّث تلقائياً.
- **الصلاحيات** (`perm`): الحذف، تعديل الأسعار، إدارة الوسوم، إدارة الحقول. لكل منها خياران: «المدير فقط» أو «الجميع». الدالة `can(k)` تفحصها و`needAdm(fn)` تغلّف العمليات الخاصة بالمدير.
- **القفل:** تسجيل دخول برمز عند الفتح، وقفل سريع، وقفل تلقائي بعد `alk` دقائق بلا استعمال (يقفل المدير أيضاً).
- **حماية من التخمين:** 5 محاولات خاطئة ثم انتظار 10 ثوانٍ.
- **لوحة أرقام** مخصصة مع تبديل إلى لوحة حروف.

> هذه حماية على مستوى التطبيق فقط: من يملك الهاتف مفتوحاً أو يصل لتخزين المتصفح يصل للبيانات المحلية. التشفير الفعلي يخص المزامنة والنسخ الاحتياطي (القسمان 6 و7).

## 5. المزامنة بين الأجهزة (`sync.js`)

**الفكرة:** كل هاتف يحتفظ بنسخة كاملة محلياً، ويتبادل التغييرات مع جدول واحد في Supabase.

### الإعداد (للمدير فقط)
من «المزيد ← الإدارة والبيانات ← المزامنة بين الأجهزة»: بريد حساب المحل + كلمة سر الحساب + رمز المحل (مفتاح التشفير). عند التفعيل تختار: رفع بيانات هذا الجهاز (أول جهاز) أو استبدالها ببيانات المحل (جهاز إضافي). عنوان المشروع والمفتاح العام (anon) ثابتان في أول `sync.js` (`SY_URL` و`SY_KEY`)، والحماية الفعلية تعتمد على صلاحيات الصفوف في Supabase وحساب المحل.

### الجدول
جدول `records` تُستعمل أعمدته: `coll` · `id` · `data` · `enc` · `deleted` · `ts` · `who` · `srv`. الصف فريد بالزوج `(coll, id)`. **ملف إنشاء الجدول (SQL) غير موجود في المستودع**، فاحتفظ بنسخة منه خارجه.

### ما يُزامَن
- **قوائم سجلات:** `items` `rp` `req` `gg` `guide` `fields` `ag` `used` `debt` `tp` (سجل لكل صف).
- **قيم مفردة:** `tags` `perm` `users` `pin` `cfg`.
- **محلي فقط ولا يُزامَن:** حجم الخط والثيم والزر العائم والعرض المضغوط والباركود السريع (`fs` `th` `fab` `cmp` `bcQuick`).
- **الصور:** تُزامَن كصفوف منفصلة (`coll=meta`، `id=img:معرّف السجل`).

### التشفير
- **مشفَّر (AES-GCM):** بيانات الزبائن فقط: `rp` `req` `used` `debt` ومحجوزات المخزون، وكذلك الصور.
- المفتاح مشتق (PBKDF2، 150000 دورة) من **رمز المحل**. إن اختلف الرمز بين جهازين تظهر رسالة «رمز التشفير لا يطابق رمز المحل».
- بقية المخزون غير مشفّر.

### سلوك الدورة
- تبدأ بعد أي تعديل (خلال 1.5 ثانية)، وكل 25 ثانية، وعند عودة الإنترنت، وعند رجوع التطبيق للواجهة.
- الإرسال دفعات (40 صفاً أو نحو 300 ألف حرف كحد أقصى للدفعة)، والسحب 200 صف في كل طلب (و12 للصور).
- مهلة الاتصال 20 ثانية، وبلا إنترنت تُعاد المحاولة تلقائياً.
- الحذف يُسجَّل «شاهداً» (`deleted`)؛ وشواهد الصور تُنظَّف بعد 90 يوماً.
- **دمج الوسوم بالجمع** عند التعديل المتوازي من هاتفين.
- **حماية من الحذف الجماعي:** إن اختفى 10 سجلات أو أكثر (وأكثر من نصف السجلات) من هذا الجهاز تتوقف المزامنة وتطلب موافقة المدير قبل المتابعة.
- **حماية من البيانات التالفة:** إن كان ملف بيانات الجهاز تالفاً عند الإقلاع تتوقف المزامنة ويُعرض استرجاع نسخة تلقائية.
- أيقونة صغيرة تعرض الحالة: متصلة / جارٍ / بلا إنترنت / خطأ / متوقفة.

## 6. النسخ الاحتياطي (`backup.js`)

| النوع | التفاصيل |
|---|---|
| **ملف يدوي** | `aziz-shop-backup-التاريخ.json` يُحفظ من المزيد. **بيانات الزبائن فيه مشفّرة برمز المدير**، ويُطلب الرمز نفسه عند الاستعادة |
| **نسخ تلقائية داخل الهاتف** | IndexedDB، بلا صور: `latest` (آخر نسخة، تُحدَّث بعد كل حفظ بنحو 5 ثوانٍ) + نسخة يومية تُحفظ **7 أيام** + `pre:` قبل العمليات الخطرة (يُحفظ **آخر 3**) |
| **ربط ملف تلقائي** | اختيارياً يمكن ربط ملف على الجهاز يُحدَّث تلقائياً بنسخة مشفّرة (يتطلب دعم المتصفح وتفعيل رمز المدير) |

> النسخ التلقائية لا تغني عن ملف النسخة الأسبوعي: هي داخل الهاتف نفسه، فإن ضاع الهاتف ضاعت معه.

## 7. بنية الكود

### القاعدة الأساسية
**لا ملف يعدّل دوال ملف آخر.** كل ملف يسجّل نفسه في سجلات `core.js`، والدوال والثوابت عامة (لا توجد وحدات `import`)، والأزرار تستدعي الدوال عبر `onclick="..."` داخل نصوص HTML.

### السجلات

| السجل | الاستعمال |
|---|---|
| `VW` | الشاشات: `VW.name = () => ({ t: 'العنوان', h: 'html', a: () => {} })` ثم `go('name')` |
| `HK` | خطّافات: `HK.save` قبل الحفظ · `HK.saved` بعده · `HK.hide` عند إغلاق النافذة · `HK.render` بعد الرسم |
| `HOME` | دوال تعيد HTML لأزرار الرئيسية: `top` · `tools` · `after` |
| `MORE` | عناصر «المزيد»: `{ g: المجموعة, l: النص, d: الوصف, fn: الاستدعاء, o: الترتيب }` |
| `SRCH` | مصادر البحث: `{ k, l, run(n) → [html] }` |
| `LM` | حدود قابلة للتعديل من الإعدادات: `[المفتاح, الوصف]` |

### أدوات مفيدة في `core.js`
`$` (عنصر بالمعرّف) · `esc` (تهريب HTML، **استعمله دائماً مع النصوص المدخلة**) · `uid` · `dg` (أرقام عربية → لاتينية) · `waNum` (رقم واتساب) · `fd` (تاريخ) · `nz` (توحيد البحث) · `save()` · `upd(fn)` (تعديل + حفظ + رسم) · `commit/del/restore` (تراجع وحذف واسترجاع) · `ask` و`sure` (نماذج وتأكيد) · `toast` · `go` · `sheetOpen/hideSheet/finish` (النافذة السفلية) · `isAdmin/can/needAdm`.

### أسبقيات الأسماء
`ph*` هواتف · `gl*` أنتي كاس · `cs*` بوشيط · `ac*`/`ag*` إكسسوارات ومجموعاتها · `rp*`/`rc*` صيانة وتقرير · `sy*` مزامنة · `tp*` تعبئة · `bk*` نسخ · `us*`/`u*` مستخدمون.

### إضافة ميزة جديدة
1. إن كانت ملفاً جديداً: أنشئه، ثم أضف `<script src="اسم.js?v=N">` في `index.html` **قبل `app.js`**، وأضف `./اسم.js` إلى `ASSETS` في `sw.js`.
2. سجّل شاشاتك وأزرارك في السجلات بدل تعديل ملفات أخرى.
3. أي حقل جديد في `S` يضاف إلى `DEF` في `core.js` (والمزامنة تتطلب إضافته إلى `SY_ARR` أو `SY_ONE` في `sync.js`، والتشفير إلى `SY_ENC` إن كان بيانات زبائن).
4. التنسيقات في `style.css` فقط.
5. ارفع رقم الإصدار (القسم 8).

### قبل حذف دالة أو متغيّر
ابحث عن اسمه **داخل النصوص أيضاً** (`onclick="اسم(...)"` وقوالب HTML)، لأن البحث في الكود وحده لا يكفي. الأسماء المعرَّفة مثل `window.اسم = …` تُستعمل كذلك من هناك.

### ترتيب التحميل
`core` → `icons` → `topup` → `inv*` (base, phones, glass, pochette, acc, report) → `invround` → `barcode` → `invcolor` → `invset` → `repair` → `report` → `sync` → `extra` → `home` → `users` → `backup` → `app`.
كل ملف يعتمد على ما قبله عند التحميل. أي استدعاء ينفَّذ لحظة تحميل الملف (خارج الدوال) لا يجوز أن يعتمد على دالة معرَّفة في ملف يليه. **`app.js` يجب أن يبقى الأخير** لأنه يبدأ التطبيق.

## 8. النشر والتحديث

الاستضافة ملفات ثابتة تُخدَّم من مجلد `v3`، والتحديث بالرفع إلى المستودع.

1. عدّل الملفات (أو استبدلها) في المجلد `v3`.
2. **ارفع رقم الإصدار في مكانين معاً:**
   - `index.html`: كل `?v=N` (في روابط الملفات وتسجيل `sw.js`) يجب أن تكون **نفس الرقم**.
   - `sw.js`: `const CACHE = 'aziz-shop-v3-N'` بالرقم نفسه.
3. تأكد أن كل ملف JS جديد مذكور في `index.html` وفي `ASSETS` داخل `sw.js`.
4. بعد الرفع راقب نتيجة الفحص في تبويب Actions (القسم 11).

### كيف يصل التحديث للأجهزة
- الـ Service Worker يطلب الملفات من الشبكة أولاً ويرجع للنسخة المخزّنة عند انقطاع الإنترنت.
- عند صدور إصدار جديد والتطبيق مفتوح يظهر شريط أزرق في الأعلى: **«تحديث جديد جاهز — أنهِ ما تكتبه ثم اضغط»**. لا تُعاد تحميل الصفحة إلا بضغط الزر، فلا يضيع ما يكتبه الموظف.
- يبحث التطبيق عن تحديث كلما عاد المستخدم إليه.
- أول تثبيت لا يعرض الشريط.

## 9. استكشاف الأخطاء

| العَرَض | السبب والحل |
|---|---|
| فشل الفحص: `MISSING FILE: x.js` | `index.html` يذكر ملفاً غير موجود في `v3`. ارفع الملف أو احذف السطر |
| فشل الفحص: `NOT IN SW.JS: x.js` | أضف `./x.js` إلى `ASSETS` في `sw.js` |
| فشل الفحص: `CROSS-FILE DUPLICATE DECLARATION ERROR` | اسم `const/let/function` معرَّف في ملفين. غيّر أحدهما (يُفحص بجمع الملفات في ملف واحد) |
| فشل الفحص: `all ?v= numbers are equal` | أرقام `?v=` مختلفة داخل `index.html` |
| فشل الفحص: `VERSION MISMATCH` | رقم `index.html` غير رقم `sw.js` |
| فشل الفحص عند ملف JS | خطأ صياغة؛ الصق آخر أسطر سجل الخطوة الفاشلة |
| التطبيق لا يتحدّث على هاتف | انتظر شريط «تحديث جاهز» واضغطه، أو أغلق التطبيق وافتحه |
| رسالة «المساحة ممتلئة» | خذ نسخة احتياطية ثم ارفع/احذف قديماً (الصور تُمسح تلقائياً بعد `rpKeep` يوماً من التسليم) |
| المزامنة: «رمز التشفير لا يطابق رمز المحل» | رمز المحل مختلف بين الجهازين |
| المزامنة: «انتهت الجلسة أو بيانات الدخول خاطئة» | أعد إدخال كلمة سر حساب المحل |
| المزامنة: «توقفت حمايةً: اختفى N سجلاً» | حذف جماعي مريب من هذا الجهاز. راجع البيانات، ثم وافق (للمدير) أو استعد نسخة |
| أخطاء داخلية صامتة | تُسجَّل في `localStorage` تحت المفتاح `shopErr` |

## 10. قواعد تجنّب الأخطاء عند التعديل

- **لا تغيّر ترتيب `<script>`** في `index.html` إلا بعد التأكد أن لا شيء يُنفَّذ عند التحميل ويعتمد على ملف لاحق.
- **لا تعدّل دالة معرَّفة في ملف آخر**؛ أضف خطّافاً أو سجّلاً بدلها.
- **لا تضع CSS داخل JS**؛ كل شيء في `style.css`.
- **مرّر كل نص مدخل عبر `esc()`** قبل وضعه في HTML.
- **لا تحذف ملفاً أو دالة** قبل البحث عن اسمها في النصوص (`onclick`).
- **عند تغيير شكل بيانات قديمة** تعامل مع غياب الحقل (فالبيانات القديمة لا تحمله).

## 11. الفحص التلقائي (GitHub Actions)

الملف `.github/workflows/check.yml` يعمل عند كل `push` وكل `pull_request`، ويفحص:

1. صياغة كل ملف `v3/*.js` (`node --check`).
2. أن كل ملف مذكور في `index.html` موجود، ومذكور في `ASSETS` داخل `sw.js`.
3. أن جمع الملفات بترتيب `index.html` في ملف واحد سليم (يكشف التصريحات المكررة بين الملفات).
4. أن أرقام `?v=` في `index.html` كلها واحدة.
5. أن رقم `index.html` يساوي رقم `sw.js`.

النجاح ينتهي بالسطر `all good (v=N)`. الفحص **لا يشغّل التطبيق**، فهو لا يكشف الأخطاء المنطقية؛ جرّب التطبيق بعد كل تحديث.
